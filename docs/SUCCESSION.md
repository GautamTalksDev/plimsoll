# Log key succession

The Ed25519 key that signs Plimsoll Log checkpoints is held by Gautam Khosla; the private half lives only as the `LOG_SIGNING_KEY` Actions secret on `GautamTalksDev/plimsoll-log` plus an offline backup outside every git working tree. If the operator stops, published history remains verifiable forever from any clone of that public repo and from CDN copies of the signed checkpoints; a successor continues the log by generating a new key, publishing its public half at `/key`, and appending under the new identity (forks do the same — they do not receive the old private key). If the private key is lost, the existing tree cannot gain new signed checkpoints under that identity and must be treated as frozen; if it is ever exposed, discard it, freeze the compromised identity, and start a new key as above.
