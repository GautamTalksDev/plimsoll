# plimsoll-log

Public storage for the [PLIMSOLL](https://github.com/GautamTalksDev/plimsoll) transparency log.

This repository **is** the log. Every append is a public git commit. Cloudflare Pages serves the committed `public/` tree at `https://plimsoll.gautamkhosla.com`. Anyone can clone this repo and verify the full history offline.

`internal/logd` in the main plimsoll repo remains the reference HTTP server for people who want to run their own log. It is not what operates this public log.

## Layout

| Path | Role |
| --- | --- |
| `log.sqlite` | Append-only Merkle log (SQLite + triggers) |
| `public/` | Static read API generated by `plimsoll-static` |
| `keys/log-public.pem` | Log Ed25519 **public** key only |
| `.github/workflows/append.yml` | Serialised write path via `repository_dispatch` |

Private signing material is never in this repository. It exists only as the Actions secret `LOG_SIGNING_KEY` (and an offline backup). See [SUCCESSION.md](SUCCESSION.md).

## How an append works

1. CLI or Worker sends `repository_dispatch` type `plimsoll-submit` with `client_payload.submit` set to a seal or attestation publish body.
2. The Action installs `plimsoll-append` and `plimsoll-static` from a **pinned** plimsoll release and verifies them with cosign before use.
3. **`plimsoll-append` is the trust gate.** It enforces the field allowlist, known `canon_version`, and Ed25519 signature verification. Extra fields or bad signatures fail the job. The Worker is not trusted.
4. A new checkpoint is signed with `LOG_SIGNING_KEY` (materialised under `$RUNNER_TEMP`, mode `600`, deleted in `if: always()`).
5. `public/` is regenerated and committed as `append: {seal|attestation} {sha256:…} idx={n}`.
6. Commit messages contain **no** user-supplied free text (no seal names, no supersede reasons).

Writes are serialised with concurrency group `plimsoll-log-append` (`cancel-in-progress: false`). Two simultaneous dispatches become two commits with consecutive indices and no gaps.

## Publish latency

An Actions run typically takes 30–60 seconds. A seal is not queryable on the CDN until the commit is pushed and Pages deploys. That is expected for pre-registration: evaluation runs take minutes to hours.

## Verify this log

```bash
git clone https://github.com/GautamTalksDev/plimsoll-log
cd plimsoll-log

# Public key used for checkpoint signatures
cat keys/log-public.pem

# Latest tree head
cat public/checkpoint

# Inclusion proof for leaf 0
cat public/proof/inclusion/0
```

Offline replay of the full Merkle history (from the main plimsoll CLI):

```bash
plimsoll verify-log --dir .
```

See [MIRRORING.md](https://github.com/GautamTalksDev/plimsoll/blob/main/docs/MIRRORING.md) in the main repo.

Or point the CLI / browser verifier at `https://plimsoll.gautamkhosla.com` (see the main plimsoll README). Verification never requires trusting only this operator: anyone can clone the git history, and `plimsoll verify` accepts any conforming log URL.

## Manual dispatch (smoke test)

With a fine-grained PAT that can dispatch on this repo:

```bash
# BODY is the exact /submit JSON (seal or attestation allowlist only)
gh api repos/GautamTalksDev/plimsoll-log/dispatches \
  -f event_type=plimsoll-submit \
  -f 'client_payload[submit]=@submit.json'
```

Or:

```bash
curl -X POST \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $LOG_DISPATCH_TOKEN" \
  https://api.github.com/repos/GautamTalksDev/plimsoll-log/dispatches \
  -d '{"event_type":"plimsoll-submit","client_payload":{"submit":'"$(cat submit.json)"'}}'
```

Expect one new commit whose message matches `append: seal|attestation sha256:[0-9a-f]{64} idx=N`.

## Operator setup (once)

1. Generate the log signing key **offline** (CP-10b.0). Never let it touch git, chat, or CI logs.
2. Store the private half as Actions secret `LOG_SIGNING_KEY` (standard base64 of the 64 raw Ed25519 private key bytes).
3. Replace `keys/log-public.pem` with the matching public half (PKIX PEM). The scaffold ships a **throwaway** placeholder PEM — replace it before the first real append, then regenerate `public/` so `/key` matches.
4. Pin `PLIMSOLL_RELEASE` in `append.yml` to a release that includes `plimsoll-append` and `plimsoll-static`.
5. Attach Cloudflare Pages to this repo’s `public/` (or repo root with `public` as the publish directory, depending on your Pages settings).

## Security notes

- Validate in the Action, not only in the Worker. The dispatch token is enough to call this workflow.
- Never echo, log, or write `LOG_SIGNING_KEY` under the working tree.
- `git log -p` must never show key material; only digests and metadata land in commits.
